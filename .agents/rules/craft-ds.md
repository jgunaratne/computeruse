# Craft Design System rules

Context: `docs/DESIGN.md` (this project's design doc and its "Deliberate deviations" table), the kit at `web/public/vendor/craft-ds/` (v0.16.0: `web/public/vendor/craft-ds/css/craft-ds.css`, `web/public/vendor/craft-ds/js/craft-ds.js`, `web/public/vendor/craft-ds/tokens/tokens.json`), and the kit's own spec `web/public/vendor/craft-ds/DESIGN.md`. Skills: `craft-new-component`, `craft-visual-check`, `craft-drift-and-align`, `craft-upgrade`. Reviewer: `craft-design-reviewer`. CLI: `~/git/craft-ds/bin/craft-ds`.

- **The kit is read-only.** `web/public/vendor/craft-ds/` is vendored and hash-pinned (`craft-ds.json` → `kit.hashes`). Never edit it; a hook blocks the attempt. Upgrade with `~/git/craft-ds/bin/craft-ds update .` (the `craft-upgrade` skill). Need something the kit lacks? Compose it in your own files, and if it is general, propose it upstream in `~/git/craft-ds`.
- **Tokens, not values.** Colour, radius and type come from `var(--craft-*)` (`colour, radius, font` are enforced): surfaces `--craft-chrome/-canvas/-dock/-card/-field`, text `--craft-text/-text-dim/-text-faint`, accent `--craft-accent/-accent-soft/-accent-border/-accent-text`, actions `--craft-primary-bg/-primary-text/-danger/-warning`, radii `--craft-radius-sm/-radius/-radius-lg`, type `--craft-font-sans/-font-mono` and `--craft-fs-heading/-button/-body/-mono/-section/-small`, shadows `--craft-window-shadow/-popup-shadow`. Neutral black/white alphas (`rgba(0,0,0,.4)`) are allowed for shadows and halos. Files in `allow_raw` (none) may hold literals; a one-off carries `craft-allow` on the line (`data-craft-allow` in markup). `~/git/craft-ds/bin/craft-ds probe .` checks (`raw-colours`, `raw-values`, `unknown-tokens`).
- **Themes are tokens; grammars are flags.** Switching `data-craft-theme` among the 14 ids restyles everything through tokens, so project CSS never contains `[data-craft-theme=…]` (`theme-patches`) and never redefines a `--craft-*` token (`token-overrides`): project tokens get their own prefix and derive from kit tokens (`--app-brand: var(--craft-accent)`). The three structural flags (`data-craft-pro`, `data-craft-bevel`, `data-craft-round-chips`, plus `data-craft-dark`) *may* be used in selectors to adapt layout, because that is what they are for; the kit sets them from the theme, so never hard-code one that disagrees with `web/public/vendor/craft-ds/tokens/tokens.json` (`grammar-flags`, `theme-ids`).
- **Kit components first.** Buttons are `.craft-btn.craft-btn-primary|secondary|danger`, `.craft-btn-compact`, `.craft-icon-btn`; fields `.craft-value-field`, `.craft-popup-value-field`, `.craft-text-field`, `.craft-dropdown`; controls `.craft-checkbox`, `.craft-toggle` (add `.is-adaptive` so Pro renders it as a checkbox), `.craft-slider`, `.craft-angle-dial`; structure `.craft-panel` + `.craft-panel-header` + `.craft-tab-strip` + `.craft-panel-body/-footer`, `.craft-menu`, `.craft-dialog`, `.craft-titlebar`, `.craft-options-bar`, `.craft-toolbar`, `.craft-status-bar`, `.craft-layer-row`. A class that starts with `craft-` must exist in the kit (`class-names`); project styles never target `.craft-*` selectors (`component-restyle`): add a project class beside the kit class and style that.
- **Icons are the kit's 161.** `<span class="craft-icon" data-craft-icon="<name>"></span>`, hydrated by `craft-ds.js`; names must exist (`icon-names`). Stroke 1.75, `currentColor`; no other icon set in the same UI.
- **Native desktop-tool feel.** Dense but legible: body type is the kit's 12–12.5 px scaled by `data-craft-font-size` (`small`, `large` are verified); numeric readouts and units use `--craft-font-mono`; Pro labels end with a colon via `.craft-pro-colon`, Studio labels don't. Every icon-only button has `aria-label` or `title` (`named-controls`); focus is visible; keyboard reaches everything.
- **Numeric fields behave like the kit's.** `input[data-craft-numeric]` inside a value field gets scrub labels (`.craft-scrub-label[data-scrub-target]`), wheel/arrow stepping and arithmetic input for free; don't reimplement those.
- **Deviate on purpose.** Anything that looks different from the kit's `index.html` showcase or from PhotoCraft is listed under "Deliberate deviations" in `docs/DESIGN.md` with a numbered entry in `docs/DECISIONS.md` (Context / Decision / Consequences). A trap that cost time goes in `docs/LESSONS.md`. Unlisted differences are drift (`deviations-logged`).
- **Look at the pixels.** After a visual change: `uv run python scripts/craft_shoot.py --url {url} --out {out} --width {width} --height {height} --theme {theme}` in `proMedium` (Pro (Medium Gray), pro grammar), `pro` (Pro (Dark), pro grammar), `proLight` (Pro (Light), pro grammar), `studio` (Studio (Dark), studio grammar), `studioLight` (Studio (Light), studio grammar), `classic` (Classic, classic grammar) at 1440, 820 px wide (one theme per grammar at least), then read every PNG with the `craft-visual-check` checklist. Then run `craft-design-reviewer`.
- **Done means proven.** `~/git/craft-ds/bin/craft-ds check .` is clean, `~/git/craft-ds/bin/craft-ds probe .` is clean or every finding is explained, screenshots were read, and the report says what ran with counts.
