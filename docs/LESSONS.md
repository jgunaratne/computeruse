# Lessons (computeruse)

Symptom → cause → rule. A trap that cost time goes here so the next agent walks around it.

- **A theme "looked fine" but the Classic shots had no bevels.** → A project button class redeclared `background`, `border-radius`, or `box-shadow` after `craft-ds.css`, overriding `.craft-btn*` and `[data-craft-bevel="true"]`. → Let `.craft-btn`, `.craft-btn-primary`, `.craft-btn-secondary`, `.craft-btn-danger`, `.craft-btn-compact`, and `.craft-icon-btn` own button chrome; keep `.btn` strictly for layout/router reset (`text-decoration: none`) and test selectors.
- **Dynamic React views rendered empty `[data-craft-icon]` spans.** → `craft-ds.js` hydrates `[data-craft-icon]` once on `DOMContentLoaded`, before conditional React panels (Chat, Schedule editor, flow menus) mount. → Keep the `MutationObserver` in `web/src/lib/appearance.ts` active on `document.body` so newly mounted or attribute-updated `[data-craft-icon]` elements hydrate immediately from `window.CRAFT_ICONS`.
- **Bright semantic status colours (`--craft-label-green`, `--craft-label-yellow`) washed out on `proLight`, `studioLight`, and `classic`.** → Saturated dark-mode swatch colours have low contrast against light cards. → Bind `--cu-ok`, `--cu-warn`, `--cu-bad`, and port/node tokens to `--craft-label-*` by default and remap them to `--craft-label-*-eye` under `[data-craft-dark="false"]`.
- **Neutral translucent colours written as `hsl(0 0% 100% / 0.08)` tripped `raw-colours`.** → The `raw-colours` probe treats `rgba(0, 0, 0, a)` and `rgba(255, 255, 255, a)` as neutral alphas, not `hsl(...)`. → Prefer `var(--craft-hover)` / `var(--craft-separator)` or `color-mix(in srgb, var(--craft-*) …, transparent)`, and use `rgba(0, 0, 0, …)` / `rgba(255, 255, 255, …)` when a neutral alpha is required.
